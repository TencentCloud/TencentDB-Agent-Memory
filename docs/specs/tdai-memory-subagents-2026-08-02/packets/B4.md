## P8 — reindex-integration (complex, db)

- **goal**: инкрементальный реиндекс по умолчанию — per-row `l1_vec` delete+insert
  по record_id (sqlite.ts:684-685; НЕ SQL UPDATE); полный `reindexAll`
  (in-process, sqlite.ts:1914) — при content-перезаписи L1, needsReindex или
  post-apply count-mismatch; ретрай SQLITE_BUSY (WAL, busy_timeout=5000);
  **reindex-write-race**: полный reindexAll под single-flight-локом, capture-политика
  на окно 2-10 мин: skip-dual-write (L0/L1-вектор-записи пропускаются, meta идут
  как обычно) + post-reindex count-reconciliation; **livelock-cap**: ретраи
  ограничены (2), при повторном count-mismatch — backfill дельты per-row вместо
  повторного полного реиндекса; **во время полного реиндекса** /recall +
  /search/memories + /search/conversations гейтятся флагом reindex-in-progress →
  пустой результат, НЕ ошибка (fail-open). **sqlite-vec: апгрейд
  0.1.7-alpha.2 → 0.1.9** (фикс DELETE-регрессии #274; 0.1.9 стабильный, 0.1.10
  alpha): перед бумпом — снапшот vectors.db (бэкап) + документированный откат
  пина; после — count-чек + KNN-sanity на живой vectors.db.
- **allowed_write_paths**: `src/core/store/sqlite.ts`, `src/core/store/types.ts`, `package.json`, `src/gateway/`,
  `docs/specs/tdai-memory-subagents-2026-08-02/**`
  (types.ts: расширение IMemoryStore optional-членами reindexL1Records/reindexL0Records/isReindexing +
  consistencyCheck-полями missingIds/l0VecCount/l0MissingIds — без них apply-executor не может
  feature-detect бэкфилл дельты и reindex-гейт на VDB-бэкендах)
- **acceptance**: юнит: per-row инкремент на фейковых записях; livelock-cap после 2
  ретраев → backfill; reindex-in-progress → recall пуст (не ошибка); skip-dual-write
  не ломает meta; sqlite-vec пин 0.1.9 в package.json + бэкап-файл vectors.db
  существует до апгрейда (проверка на фейковой БД). Typecheck/build зелёные.
- **read_context**: src/core/store/sqlite.ts (:684-685, :741, :1344, :1914),
  scripts/reindex-embeddings.ts, package.json (sqlite-vec 0.1.7-alpha.2),
  src/core/hooks/auto-recall.ts + auto-capture.ts (гейты), src/gateway/server.ts.
- **non_goals**: не менять recall-кнобы (INVARIANT nogo-recall-knobs); не трогать
  L0 capture-путь (INVARIANT nogo-l0-path); апгрейд sqlite-vec — только после
  бэкапа и с документированным откатом.
- **escalation_triggers**: апгрейд sqlite-vec сломал чтение живой vectors.db
  (KNN-sanity fail → откат пина).
