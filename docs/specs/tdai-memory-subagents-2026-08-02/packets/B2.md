## P4 — apply-executor (complex, db)

- **goal**: `POST /memory/apply` через выделенный модуль ApplyExecutor (SRP:
  оркестратор = sequencing/spawn/report; ApplyExecutor = manifest recheck + backup +
  abort-цикл + syncSceneIndex): zod ^4.4.3 `z.strictObject()` валидация diff.json
  (deleteL1 ids[]/merge clusters→target/rewriteBlock path+content/rewritePersona
  content) + семантические guardrails (ids ⊆ диффа, targets ⊆ records, allowlist
  путей scene_blocks/**/persona.md, batch-капы), safeParse; дубли —
  `deleteL1Batch` boolean (sqlite.ts:1344 → abort на false) / `writeMemory` async
  (l1-writer.ts:163 → try/catch, abort на null/throw); **stale-delete-race**:
  дифф несёт per-id updatedAt, re-check при apply, pre-check отсутствующей мишени
  = уже применено → skip, abort только на updatedAt-дрейфе; порядок мутаций:
  write до delete, файлы после DB; **post-apply vec-vs-meta count-чек: оба COUNT в
  ОДНОЙ read-транзакции + orphan-diff in-process (id-set) + per-id delete через
  stmtDeleteVec в одной транзакции**; count-match → commit, mismatch →
  needsReindex+reindexAll (livelock-cap §5.6), unresolved → run failed+отчёт;
  **partial-apply**: abort на mid-loop → heal (re-run скипает уже-применённые,
  применённые в отчёте); scene/persona атомарно с бэкапом; syncSceneIndex (ошибка
  → run failed + rebuild на следующем /memory/validate); trust-boundary манифест:
  baseline на спавне (scene_blocks/**, persona.md — mtime+хэш), recheck перед
  apply, дрейф → abort; НЕ включать records/vectors (их пишет гейтвей).
- **allowed_write_paths**: `src/gateway/`, `src/core/`, `docs/specs/tdai-memory-subagents-2026-08-02/**`
- **acceptance**: юнит-тесты: (c) невалидный diff.json → прервано, частичного
  apply нет; runtime-сбой deleteL1Batch=false → abort; stale-delete drifted
  updatedAt → abort, свежие не теряются; (i) heal re-run на 2-й мутации → повторный
  прогон скипает применённые и завершает остаток; (a) негативный write-путь:
  child пишет в scene_blocks напрямую → манифест-дрейф → abort; count-чек на
  фейковых векторах. Typecheck/build зелёные.
- **read_context**: src/core/store/sqlite.ts (:1344 deleteL1Batch, :684-685 per-row
  l1_vec delete+insert, :1914 reindexAll), src/core/record/l1-writer.ts (:163/237),
  src/core/scene/scene-index.ts, zod v4 API (z.strictObject, safeParse,
  z.treeifyError).
- **non_goals**: не менять l1-dedup/промт; records вне apply не переписывать.
- **escalation_triggers**: потеря данных при abort-тестах на живой БД (тесты на
  фейковой БД); пустой vector после apply.

## P5 — single-writer-gate (standard)

- **goal**: при `memory.consolidation.enabled` гейтить инлайн L2/L3-раннеры в
  фабрике `createL2Runner`/`createL3Runner` (src/utils/pipeline-factory.ts:429/608,
  call-site tdai-core.ts:477/491 + seed-runtime.ts:109/119; pipeline-manager.ts
  только сеттеры); no-op + warnOnce-лог при активации; документированный контракт:
  seed (executeSeed server.ts:734 / Commander `memory-tdai seed --input <file>`,
  НЕ bun run seed — скрипта нет) при enabled выдаёт только L1. Дефолт enabled=false
  — текущее поведение. L1-экстракция остаётся в гейтвее.
- **allowed_write_paths**: `src/utils/pipeline-factory.ts`, `src/core/tdai-core.ts`,
  `src/core/seed-runtime.ts`, `docs/specs/tdai-memory-subagents-2026-08-02/**`
- **acceptance**: юнит-тест фабрики: enabled=true → createL2Runner/createL3Runner
  возвращают no-op (load-bearing assert); enabled=false → текущее поведение;
  warnOnce присутствует. Typecheck/build зелёные.
- **read_context**: src/utils/pipeline-factory.ts, src/core/tdai-core.ts,
  src/core/seed-runtime.ts, src/core/pipeline-manager.ts.
- **non_goals**: не менять pipeline-manager setter-логику.
- **escalation_triggers**: гейт случайно зацепил L1-путь (INVARIANT nogo-l0-path).
