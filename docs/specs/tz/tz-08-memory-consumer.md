# TZ-08: контракт потребителя памяти — pi / Claude Code / Codex (Phase 7)

> Источник: производный пакет, [agent-architecture.md](../agent-architecture.md) §3.6 (две границы host-agnostic), §5 (`nogo-l0-path`, `consumer-parity`), §8 шаг 16
> Факт-чек кода: 2026-08-10

## Контекст

Host-agnostic — это **две независимые границы**, и до сих пор пакеты закрывали только первую:

| | производитель (роль) | потребитель (сессия) |
|---|---|---|
| что делает | строит кандидата, ядро применяет | читает recall, пишет заметку в L0 |
| граница | `RoleLauncher` (tz-06) | HTTP `/memory/*` + обёртка |
| смена хоста | новый launcher | обёртка под новый хост |

Требование владельца «память адаптирована и для Клода, и для Кодекса» относится именно к потребителю. Сейчас:

- серверная сторона есть: `GET /memory/search` (auth-free loopback) и `POST /memory/note` (write-gate: Bearer либо `x-memory-token`) — `src/gateway/memory-tools.ts:1-9`;
- MCP-поверхность даёт **pi-расширение вне репозитория**. **MCP-сервера в репо нет** — это комментарий в шапке `memory-tools.ts`, а не код. Значит «Claude Code и Codex ходят в память по MCP» требует написать обёртку, а не переиспользовать существующую;
- `POST /memory/note` вливается в существующий capture-путь и **не заводит второй** — `INVARIANT nogo-l0-path` (`memory-tools.ts:99`). Обёртка обязана это сохранить.

## Цель

Одинаковый доступ к памяти из сессии под любым из трёх хостов, без второго пути записи L0.

## Ожидаемый результат

- Хост-нейтральная обёртка над двумя эндпоинтами, работающая под pi, Claude Code и Codex.
- Одинаковый ответ на одинаковый запрос независимо от хоста.
- Единственный путь записи L0 сохранён.

## Scope

**Входит:**

- Обёртка над `GET /memory/search` и `POST /memory/note` в форме, потребляемой каждым из трёх хостов.
- Контрактный тест обёртки: один запрос — идентичный ответ под всеми хостами.
- Явная модель авторизации: что доступно без токена, что под write-gate.

**Не входит:**

- Расширение серверного API: пакет использует существующие эндпоинты, а не добавляет новые.
- Исполнение ролей — tz-06.
- Корни путей и auth-root — tz-07.

**Инварианты пакета:**

| Инвариант | Проверка |
|---|---|
| `nogo-l0-path` | `[t]` `POST /memory/note` не создаёт второй путь записи L0 (`memory-tools.ts:99`) |
| `consumer-parity` | `[t]` contract-тест обёртки: один запрос → идентичный ответ под pi, Claude Code и Codex |

## Зависимости

Предшественник — tz-05 (серверная сторона D1: scope как атрибут, работа по HTTP-контракту без pi-путей). От tz-06 не зависит и не блокирует его: launcher и потребитель — независимые границы. Идёт после cutover (§8 шаг 16 модели).

## Требования (функциональные)

- **D1a**: обёртка не дублирует логику сервера — только транспорт и форма вызова конкретного хоста.
- **D1b**: набор операций одинаков на всех хостах. Хост, где операция невозможна, объявляется несовместимым явно, а не отдаёт урезанный набор молча.
- **D1c**: модель авторизации переносится как есть: чтение — loopback без токена, запись — под write-gate. Обёртка не ослабляет гейт и не носит токен там, где он не нужен.
- **D1d**: `nogo-l0-path` сохраняется: запись идёт в существующий capture-путь.
- **D1e**: ошибки сервера доходят до вызывающей стороны различимо (отказ авторизации, недоступность, некорректный запрос), а не схлопываются в «не получилось».

## Критерии приёмки

1. `[t]` Один и тот же поисковый запрос под тремя хостами даёт идентичный ответ.
2. `[t]` Запись через обёртку появляется в L0 ровно один раз и попадает в L1-извлечение штатным путём.
3. `[t]` Запись без токена отклоняется; чтение без токена работает.
4. `[a]` В обёртке нет второй копии серверной логики поиска или извлечения.
5. `[t]` Недоступный gateway даёт различимую ошибку, а не пустую выдачу, которую вызывающая сторона примет за «ничего не найдено».

## План

1. Зафиксировать форму вызова для каждого из трёх хостов.
2. Реализовать обёртку поверх существующих эндпоинтов.
3. Контрактный тест на идентичность ответа.
4. Проверить `nogo-l0-path` тестом, а не чтением кода.

## Самостоятельная проверка (не тестами исполнителя)

**S1. Один запрос — один ответ на трёх хостах.**
Выполнить один и тот же поиск из сессии под pi, Claude Code и Codex.
→ Ответы идентичны. Различие в форме описания инструмента допустимо, различие в наборе или содержании результата — нет.
Фальсификация: изменить что-нибудь на **серверной** стороне (например порог выдачи) — ответы обязаны измениться одинаково на всех трёх хостах. Если один остался прежним, он отвечает не от сервера, а из своего кэша или своей логики.

**S2. Запись попадает в память ровно один раз.**
Написать заметку через обёртку, затем найти её.
→ Одна запись, прошедшая штатное L1-извлечение. Двух копий нет.
Это прямая проверка `nogo-l0-path` (`memory-tools.ts:99`): второй путь записи проявится именно как дубль.

**S3. Гейт записи не ослаб.**
Попробовать записать без токена и прочитать без токена.
→ Запись отклонена, чтение работает. Обёртка не должна «на всякий случай» носить токен туда, где он не нужен.
Фальсификация: выполнить запись **с** корректным токеном — она обязана пройти. Отказ в обоих случаях означает, что запись сломана вовсе, а не что гейт работает; это разные вещи, и первое легко принять за второе.

**S4. Недоступность отличается от пустоты.**
Погасить gateway и выполнить поиск.
→ Приходит различимая ошибка, а не пустой список.
Это не косметика: пустой список читается как «в памяти ничего нет», и сессия запишет то, что уже есть, — так рождаются дубли.

**S5. Логика не продублирована — проверяется сервером, не чтением кода.**
Изменить поведение на серверной стороне (порог, множитель, порядок выдачи) и, ничего не меняя в обёртке, повторить тот же запрос.
→ Ответ обёртки изменился ровно так же, как ответ прямого HTTP-вызова.
Чтение кода тут не доказательство: продублированную логику легко не заметить, а совпадение ответов при изменённом сервере воспроизвести, не имея её, невозможно.
Фальсификация: сравнить с прямым `curl` к тому же эндпоинту — расхождение и есть та самая вторая копия логики.

## Нефункциональные

- Обёртка не добавляет заметной задержки к вызову: это транспорт, а не слой обработки.
- Недоступность gateway не роняет сессию пользователя.

## Риски

- **R1 (medium)**: соблазн реализовать поиск на стороне обёртки ради скорости. План: `[a]`-чек на отсутствие второй копии логики.
- **R2 (medium)**: пустая выдача при недоступном gateway читается как «памяти нет» и приводит к повторной записи того же. План: различимая ошибка — отдельный критерий приёмки.
- **R3 (low)**: хосты по-разному описывают инструменты. План: расхождение — в форме описания, а не в наборе операций; набор фиксирован.

## Risk tier

**Tier-2**, с **security**-элементом: обёртка касается write-gate и токена. Ослабление авторизации недопустимо.

## Откат

- Обёртка аддитивна: её отсутствие возвращает текущее состояние (память доступна только под pi).
- Серверные эндпоинты не меняются, поэтому откат не затрагивает данные.

## Глоссарий

- **Потребитель памяти** — сессия, которая читает recall и пишет заметки; не роль.
- **Write-gate** — авторизация записи (Bearer либо `x-memory-token`).
- **nogo-l0-path** — запрет на второй путь записи L0.
