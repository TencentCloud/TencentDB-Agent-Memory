# AGENTS.md — TencentDB-Agent-Memory

## Архитектура памяти: двухсторонняя инфраструктура

Память tdai-memory работает через **два независимых слоя**:

### Слой 1: TDAI Gateway (этот репозиторий)

Код в `src/` — это **infrastructure layer**. TDAI делает ровно две вещи:
1. **Отдаёт задачу агенту** — запускает pi с ролью через `RoleLauncher`
2. **Забирает результат** — читает `diff.json` из scratch и применяет через `/memory/apply`

**TDAI НЕ знает и НЕ хочет знать:**
- Что происходит внутри pi-сессии агента
- Есть ли критик, как он вызывается, что он проверяет
- Какой pipeline внутри роли (task-simple, свой цикл, что угодно)
- Какие subagent'ы спавнятся внутри

### Слой 2: Pi Subagent Roles (вне этого репозитория)

Всё что касается внутренней работы роли — живёт в **системном промпте роли** и **пайплайне в самом pi**:

**Keeper skills** (`~/.pi/agent/skills/`):
- `memory-keeper/` — пчёлка консолидации
- `night-keeper/` — ночной уборщик
- `dedup-daily/` — ежедневная дедупликация

**Critic skills** (`~/.pi/agent/skills/`):
- `memory-critic/` — критик пчёлки
- `night-critic/` — критик ночного уборщика
- `dedup-daily-critic/` — критик дедупликации

### Принцип минимальной связанности

**TDAI и pi должны быть минимально связаны.** TDAI отдаёт задачу и забирает результат. Что внутри pi — не дело TDAI.

### Принцип роль-скилл-критик

**Каждая роль работает через свой скилл с критиком.** В конце системного промта каждой роли должно быть упоминание: «работай через свой скилл, спавни критика через subagent, проверь вердикт, финализируй diff.json только при ok».

**TDAI НЕ знает о критике.** Поле `critic_role` в role.json не должно существовать. TDAI не спавнит критика, не парсит verdict, не проверяет receipt. Всё это внутреннее дело pi-роли.

**Критик — это pi subagent role**, живущий в `~/.pi/agent/skills/`. Keeper спавнит его через `subagent` tool, как task-simple спавнит `critic`. Критик проверяет артефакты, возвращает вердикт. Критик ok → keeper финализирует diff.json. Keeper возвращает результат в TDAI.

### Модели

Все роли используют `xiaomi-token-plan-sgp/mimo-v2.5` (MiMo v2.5).
