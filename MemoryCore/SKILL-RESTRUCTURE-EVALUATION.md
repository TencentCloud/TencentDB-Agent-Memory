## 2. 内容整理的实际变化

### 重复记录变成可用规则

排障样本中，第 118 条历史记录包含一条少见但重要的约束：**证书校验失败时，不得关闭 TLS 证书验证。** 整理后，这条规则进入主流程，而不是跟随流水账一起删除。

保留下来的内容还包括：

- 生产变更和重启的审批要求；
- 密码、访问 token 不进入日志；
- 探测超时保持 **5000 ms**；
- DNS、TCP、TLS、认证、连接池的检查顺序；
- 先取只读证据，修复后使用相同探测验证，并报告失败层、证据和结果。

实际结果中的规则节选：

> Keep the connection timeout at 5000 ms for the diagnostic probe; do not silently increase it to hide a failure.
>
> Check DNS resolution, then TCP reachability, then TLS negotiation, then authentication, then connection-pool saturation.

原有 SQL 探测脚本和二进制附件的字节及属性保持不变。缩短的是重复历史，不是有效约束。

### 独立能力有自己的入口

混装样本整理后，原入口保留 MySQL 排障；`frontend-accessibility-review` 作为独立能力，保留自己的触发条件和检查流程：

- 仅键盘操作、可见焦点与合理焦点顺序；
- 表单可访问名称和读屏错误播报；
- WCAG AA 文本对比度；
- 不能只凭自动扫描结果宣称无障碍合规。

原入口提供子能力导航，不再承担两套无关的完整流程。资产登记、独立更新、父子版本和资源读取链路由本地集成测试另外验证，见[测试记录](./SKILL-RESTRUCTURE-TESTING.md)。

### 重复操作成为脚本，报告格式成为模板

健康探测样本整理成以下包结构：

```text
https-health-diagnostics/
├── SKILL.md                         触发条件、全局约束、调用和主流程
├── scripts/probe_https_health.py    可复用的只读 HTTPS 探测
├── references/interpretation.md     各类结果的解释与停止条件
└── templates/health-report.md       可复用报告骨架
```

这组结果的入口、脚本、参考说明和模板合计 **12,625 个文本字符**，相对原稿的 42,006 字符，内容既得到提炼，也形成了可执行和可复用的组织方式。

## 3. 独立审核确实拦住了什么？

### 规则被缩窄

短候选样本的第一份草稿恢复了 TLS 规则，但把原包要求的“**所有生产变更都需审批**”缩窄到部分操作。独立审核拒绝了这份结果。

通过真实引擎的有界修正流程，新的写作者恢复通用审批要求，新的审核上下文确认原版约束被保留。这说明审核不是只判断候选“看起来通顺”，也会检查已经从候选里消失的原始规则。

### 生成脚本存在边界缺陷

健康探测脚本的第一份版本，把没有显式端口的 IPv6 主机名传给 `HTTPSConnection` 时，可能被错误解析。独立审核发现并拒绝了该版本。

修正轮次将省略的 HTTPS 端口明确设为 443，同时保留显式端口。新的独立审核通过了修正后的包。最终脚本没有由人工直接改写来获得通过结果。

## 4. 结果还能指导任务吗？

两个额外的独立模型上下文分别只接收原包、或只接收整理后的包，回答相同场景：

1. DNS/TCP 成功，但 TLS 证书校验失败；有人建议关闭验证或增加超时，且未获得生产变更授权。
2. 自动无障碍扫描为绿色，是否可以直接宣称合规？

前后两组均保留了关键判断：不跳过 TLS，不提高 5000 ms 超时来掩盖失败，不擅自变更生产或记录凭据；取证并请求审批，明确尚未验证的结果。无障碍检查仍要求人工键盘、焦点、读屏、表单名称与对比度验证。

这是**任务决策对照**，没有实际操作生产数据库或浏览器，也不等于对所有任务作出等价性证明。

## 5. 生成脚本的执行验证

独立审核通过并检查源码后，对该次生成的 Python 脚本进行了 **26 项检查，全部通过**：

- 24 个子进程场景，覆盖本地 HTTPS 的正常/异常响应，以及无请求的非法输入：布尔 readiness、缺失字段、非对象/非法 JSON、NaN、大小边界、截断响应、重定向、HTTP 429/503、URL 凭据/参数/片段、参数错误、不受信任证书和 5 秒超时。
- 2 项标准库构造检查，验证 IPv6 默认端口和显式端口路由；不需要访问外网或绑定特权端口。

到达 HTTP 的场景只产生一次 GET；非法输入和证书拒绝场景没有产生 HTTP 请求。合成的敏感输入/响应内容没有进入输出。执行环境为 Python 3.14，另检查了 Python 3.9 语法兼容性；使用临时本地 CA，没有修改系统信任库。

这验证的是该次生成并审核后的脚本，不表示生产流程会自动执行任意模型生成的代码。

## 6. 评估方法与记录口径

- 写作者和审核者使用独立的 Claude Fable 5 上下文；调用的是真实语义引擎工具和校验器，不用固定草稿替代模型结果。独立上下文不等于不同模型家族。
- 部分评估复用了已记录的真实工具调用，再接入新的审核或修正上下文。重放逐项检查工具结果一致性，不计作新的完整模型评估，也不用于宣称四轮调用的总时延。
- 重复历史样本曾因审核未及时接入而超时；其他个别接入尝试因轮询或命令校验结束。这些没有有效审核结果的尝试不统计为通过。最终统计使用实际完成的记录。
- 修正后的代码还重放了五组已完成记录，工具结果、输入指纹和最终输出保持一致。此项属于回归验证，新增真实模型调用数为 0。
- 没有 provider 的输入/推理 token 总量，因此不报告 token 成本或速度收益；云端 TCVDB/COS 与生产模型服务未实测。

固定样本和运行方法见[测试计划](./SKILL-RESTRUCTURE-TESTING.md)。本地证据包括原包、候选、调用记录、指纹、审核、最终结果及脚本执行记录；它们与自动化测试结果分开统计。
