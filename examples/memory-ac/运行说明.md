# A+C 本地复现与运行说明

本代码实现“来源受控评测 → 反馈获取 → 有界策略学习 → MemoryCore 检索选择”的闭环。建议先用离线验证检查结果，再按需运行实际 Gateway 和公开数据。所有命令均在本 `code` 目录执行；不需要原研究工作区、私有镜像或付费 API。

## 先跑通：无需 GPU、网络和模型

环境：Node.js >= 22.16；本次验证为 Windows、Node 24.11.0。

```sh
npm test
npm run verify
node scripts/verify-residual.mjs
node scripts/fit.mjs evidence/feedback-pairs.jsonl evidence/models.json refitted-model.json
```

第一条预期为 14 项测试通过。第二条会重新检查逐题数值、重拟合四个模型，并重算十二组配对统计：

```json
{
  "status": "pass",
  "questions": 828,
  "training_questions": 272,
  "evaluation_questions": 556,
  "method_views": 7452,
  "refitted_models": 4,
  "recomputed_primary_bootstrap_contrasts": 12
}
```

第三条额外重拟合 R-Q、R-A 和随机极性残差头，预期 `refitted_residual_models: 3`、`exact_parameter_equivalence: true`；输入是 171 对 QA 与 9 对来源偏好，逐项检查来自 LongMemEval 训练集。第四条将四个组合模型写到新文件，不会激活策略或覆盖原参数。再次执行时请使用新的输出名。离线验证复现冻结结果的计算和训练；重新生成模型回答使用后面的全链路命令。

## 实际 MemoryCore 写入、检索与回退

```sh
npm run bootstrap
npm run test:gateway
```

需要 Git、npm 和网络。bootstrap 在当前目录创建独立 `vendor/TencentDB-Agent-Memory`，固定 tag `v2.0.0-beta.1` 与提交 `41444344ce11467a5b5ad6aa032f5e261da1f4d2`，安装锁定依赖，不修改父目录的仓库。

Gateway 测试使用本地 SQLite、实际 HTTP 接口与隔离 worker，预期 9 项检查通过：关闭优化、开启后与离线一致、读取失败、元数据超时、模型损坏、来源映射损坏、CPU 挂起、评分超时、原生错误传播。这里的固定评分器与小型样例用于联通测试；真实 Qwen 测量保存在 `evidence/runtime.json`。

tag 本身不提供 lockfile。`repro/MemoryCore.clean.package-lock.json` 修复了原研究锁中四项可选 WASM 依赖解析，供干净安装；原锁也保留。MemoryCore 源码和检索算法均未修改。

## 从公开数据运行完整实验

以下以 BEAM 1M 为例，与随包的 Reader/Judge 配置对应。完整运行需要 CUDA GPU、本地 Ollama，以及 Python + pyarrow。数据和模型各自遵循原项目许可，下载脚本校验固定版本。

### 准备数据和模型

```sh
node scripts/download.mjs beam
python scripts/v9-beam-export.py
node scripts/download.mjs reranker
```

BEAM 导出需要 pyarrow；安装配置见 `config/requirements-v9.txt`。分组清单在 `evidence/beam-split.json`。保护集不参与评分与拟合。

重排器已验证的 Windows 环境为 Python 3.14、BF16/CUDA。可按以下命令建立独立环境：

```powershell
py -3.14 -m venv runtime/v9-python
runtime/v9-python/Scripts/python.exe -m pip install torch==2.11.0+cu128 --index-url https://download.pytorch.org/whl/cu128
runtime/v9-python/Scripts/python.exe -m pip install -r config/requirements-v9.txt
```

将上面导出命令的 `python` 指向已安装 pyarrow 的环境。重排器的模型 revision 与权重哈希见 `evidence/reranker-source.json`。本地 Ollama 配置为 0.34.0，安装 `qwen3.5:9b` 和 `gemma3:12b` 后核对 `config/reader.json`、`config/judge.json` 中 digest。配置匹配失败时先检查版本，不要无记录地换模型。

### 写入、重排与选择

```sh
node --import ./vendor/TencentDB-Agent-Memory/MemoryCore/node_modules/tsx/dist/loader.mjs scripts/ac-ingest.mjs --adapter beam --data data/beam-v9/export-v9.0/1M.jsonl --split calibration --out runs/ingest-beam --runtime runtime/ingest-beam --expected-questions 180
node scripts/ac-score.mjs --records runs/ingest-beam/records.jsonl --out runs/scored-beam --runtime runtime/scorer-beam
node --import ./vendor/TencentDB-Agent-Memory/MemoryCore/node_modules/tsx/dist/loader.mjs scripts/select.mjs runs/scored-beam/bundle.jsonl evidence/models.json runs/selected-beam
```

预期得到 180 道问题、9 种方法共 1620 个视图，以及对应 references。ingest 先独立查询原生 k5，再请求 P32；select 使用同一冻结策略生成全部模式。评分服务绑定 `127.0.0.1:18431`，终止时仅清理本流程创建的进程。

### 回答、判定与聚合

```sh
node scripts/ac-eval-v1-1.mjs --views runs/selected-beam/views.jsonl --references runs/selected-beam/references.jsonl --adapter beam --phase reader --config config/reader.json --cache runtime/qa-cache --out runs/answers-beam
node scripts/ac-eval-v1-1.mjs --views runs/selected-beam/views.jsonl --references runs/selected-beam/references.jsonl --adapter beam --phase judge --config config/judge.json --cache runtime/qa-cache --out runs/judgments-beam --answers runs/answers-beam/results.jsonl
node scripts/aggregate.mjs runs/selected-beam/views.jsonl runs/judgments-beam/results.jsonl runs/beam-report.json
```

依次输出回答、判定和模式汇总 JSON。核对 `status`、题数、模式、正确数、来源指标、token、失败记录与配对区间。输出目录必须是新目录，所有方法在同一次协议下运行。

### LongMemEval 与新数据

```sh
node scripts/download.mjs longmem
node scripts/prepare-public.mjs longmem data/longmemeval_s_cleaned.json data/prepared-longmem
node --import ./vendor/TencentDB-Agent-Memory/MemoryCore/node_modules/tsx/dist/loader.mjs scripts/ac-ingest.mjs --adapter normalized --data data/prepared-longmem/subjects.jsonl --split development --out runs/ingest-longmem --runtime runtime/ingest-longmem --expected-questions 96
```

prepare 使用记录的 168 个 ID，保留 72 训练／96 开发；一个完全空的非 gold 消息有审计记录，gold 不被静默跳过。随后按相同评分链运行，但需要选择匹配数据的评测适配器与新配置。

本地通用写入器按 subject 隔离，而历史 LongMemEval 使用十三个共享 shard，所以新写入协议标记为 `ac-delivery-reingest-v1`，必须重跑同批基线。离线冻结结果验证不受该变化影响。模型、上下文窗口、写入隔离或裁判规则变化都应记录新协议版本。

## 反馈闭环：继续训练自己的策略

输入为明确标记 `train` 的标准化评分 bundle，以及固定 Qwen、R-Q、R-A 三种候选的 QA 判定：

```sh
node --import ./vendor/TencentDB-Agent-Memory/MemoryCore/node_modules/tsx/dist/loader.mjs scripts/feedback.mjs prepare TRAIN_BUNDLE PRIMITIVE_JUDGMENTS evidence/models.json runs/feedback
# 对 runs/feedback/views.jsonl 与 references.jsonl 使用相同 adapter/config 做 Reader、Judge 评测。
node --import ./vendor/TencentDB-Agent-Memory/MemoryCore/node_modules/tsx/dist/loader.mjs scripts/feedback.mjs collect runs/feedback/plan.json INTERVENTION_JUDGMENTS runs/new-pairs.jsonl
node scripts/fit.mjs runs/new-pairs.jsonl evidence/models.json runs/candidate-model.json
```

大写位置是需要替换的输入文件路径。prepare 在观察移除结果前固定主动／随机采样计划；collect 只把“原正确、控制正确、支持错误”的匹配样本转成 A 偏好。没有匹配来源的样本保留排除原因。fit 仅输出候选模型，部署前在固定开发协议上与同批基线比较。

TDAI 镜像接入通过 `BoundedGatewayClient({baseUrl,apiKey,serviceId,timeoutMs})`，鉴权放环境变量或宿主密钥管理。配置地址后检查 `/v2/conversation/add`、`/v2/conversation/search` 的兼容性，即可复用数据写入、检索选择、日志与反馈训练逻辑。实际 Gateway 验证入口为 `npm run test:gateway`。

## 常见排查

| 现象 | 处理 |
| --- | --- |
| 输出路径已存在 | 换一个新目录／文件，避免覆盖冻结结果 |
| tsx loader 不存在 | 先运行 npm run bootstrap |
| pyarrow 不存在 | 在执行导出的 Python 环境安装 requirements 中对应依赖 |
| CUDA / BF16 不匹配 | 使用记录的 CUDA 环境；换精度需作为新协议重跑全部模式 |
| 模型 digest 不符 | 核对 Ollama 模型版本及配置，不跳过校验 |
| fallback=true | 检查 reason、请求 ID 和阶段时间；关闭或故障应走新鲜原生 k5 |
| 结果数与预期不符 | 按计划题数核对逐题状态、失败计数和来源指标分母 |

数值算法与离线验证为跨平台 JavaScript；GPU 启动器的验证环境为 Windows。其他系统通过启动器适配运行，并以 Gateway 故障测试核对进程清理行为。数据、模型和凭据分别通过下载入口、配置与宿主密钥管理加载。
